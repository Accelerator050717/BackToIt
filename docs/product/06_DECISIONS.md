# 产品与工程决策记录

日期：2026-10-22。研究原型的范围决策已采用；正式产品建议均为 Proposed，须经过[发布关卡](09_RELEASE_GATES.md)。决策者：本轮产品/UX/工程代理，未代替用户或受访者做产品批准。

## Context

已交付的 v0.1 能保留现场，用户新增的只是一个朋友情境，没有访谈或使用分析。可用时间首先应买到“该不该做”的信息，同时保留一个可真实操作、可否定假设的原型。

## Decision

| ID  | 本轮真正采用的选择                                            | 两个以上实际替代方案与未选原因                                                                                                |
| --- | ------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| D01 | Resume保持主入口，歇一下只做次级主动入口                      | 以娱乐首页作为主入口会偏离返回任务；以自动弹出触达需要监测、误报和额外权限，而当前需求强度未验证                              |
| D02 | C留白休息为默认研究候选；B单轮接线可比较；D无内容返回必须保留 | 只做小游戏不能检验是否本身增加负担；只做C无法比较趣味价值；直接否决所有休息也无法检验朋友情境                                 |
| D03 | A知识惊喜暂不实现，记录候选而不编卡片                         | 有限本地精选卡可控但需事实/主题维护且吸引力未知；联网或模型生成卡增加事实质量、隐私和无尽内容风险，无本轮必要性               |
| D04 | 默认90秒，仅作45/90/180研究候选中的中间值                     | 45秒可能尚未站起就结束；180秒可能增加一次进入成本。没有证据支持任一时长最优，选择90不宣称科学效果                             |
| D05 | 允许提前结束、今天先放下和最多一次显式延长                    | 禁止提前结束会削弱自主性；无限延长/推荐下一轮会将娱乐层变成持续停留机制；完全不允许延长可能逼用户另找入口                     |
| D06 | 绑定taskId和已提交nextStep/revision；返回前再核对             | 仅用currentTaskId在pause后丢目标；复制整个Task/所有资源会增加敏感副本和过期问题；不核对revision会忽略另一窗口变更             |
| D07 | 独立Vite/React网页、纯CSS与命名空间样例存储；不导入生产App    | 在正式扩展加一个实验开关仍可能写真实DB或进入安装包；静态设计稿无法验证计时、关闭重开和键盘；另起后端/账号无研究收益           |
| D08 | 采用MIT的PRD编写/复核方法和微软证据来源方法；不安装外部脚本   | 完全不审查方法会漏掉问题/指标/边界；安装整套PM库增加不必要配置；直接改写NC-SA库模板使未来复用许可复杂化                       |
| D09 | 先做同任务小样本交叉体验，不做虚假A/B成效结论                 | 直接大规模A/B没有真实流量和知情数据；只问喜欢程度无法发现结束困难；先上传遥测违背本地优先和默认不追踪                         |
| D10 | 手机只写长期方案与成本，不承诺本轮感知或拦截                  | 二维码仅可打开公共原型URL，不能同步本机私密任务；PWA/移动伴侣+同步有身份、冲突、隐私成本；监控App或系统限制超出Chrome扩展能力 |

## Consequences

| 决策 | 收益                             | 明确代价 / 未知                            | 证据强度与推翻条件                                                                                |
| ---- | -------------------------------- | ------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| D01  | 保留产品定位和好状态不被打断     | 主动入口可能没人想开                       | 用户转述弱证据；若真实需要触达，先研究opt-in入口而非立即加全站监测                                |
| D02  | 允许发现“游戏反而更差”           | 需维护多条实验路径，B仍可能有负担          | [微休息与游戏化证据](03_COMPETITORS_EVIDENCE.md)迁移有限；若B更易结束且无反复停留问题，可重新评估 |
| D03  | 无内容事实错误和维护系统         | 可能错过吸引力较强的形式                   | 无直接证据；若用户明确提出有限事实卡且有可维护来源，再做小成本独立比较                            |
| D04  | 简单一致且可调                   | 默认数字会影响体验                         | 纯设计假设；若多人提前退出或认为太短，以观察调整，不把均值包装最优                                |
| D05  | 保留退出控制和可预期边界         | 延长限制仍可能不贴合长休息                 | 保护原则；若反复需要长休息，应允许离开工具，而非继续堆轮次                                        |
| D06  | 避免回错任务、覆盖新内容         | 增加版本冲突解释和正式测试成本             | 代码证据高；未来若不复制文字能保持清晰，可改为只读目标引用                                        |
| D07  | 没有生产DB/权限变化，可快速重置  | 不能证明真实扩展侧栏、服务worker、手机能力 | 工程可检验；通过研究Gate后再投入真实扩展集成                                                      |
| D08  | 需求可测试、来源明确、无安装风险 | 需要自行整合而非自动套模板                 | 已读skill/许可证；若外部版本许可变化，按固定版本保留或更换                                        |
| D09  | 先理解真实行为和负例             | 小样本不具总体推断能力                     | 尚未招募；若需求证据不足则继续访谈或停止，不以更多原型掩盖                                        |
| D10  | 能力承诺诚实、数据边界清楚       | 无法触及手机转移的主要场景                 | 权限事实高、价值判断低；只有独立移动研究支持且用户授权后才立项                                    |

## Alternatives Considered

核心替代是“先只优化Resume”。如果参与者认为返回卡已经足够、进入休息是多余操作，应选择这条路线；它不是失败备选。另一条真实替代是“只做D无内容岔路口”，其成本与内容负担更低；若C和B没有可指出的额外价值，就删除它们的正式开发候选。

方案比较及后续决策阈值分别在[机会地图](04_OPPORTUNITY_MAP.md)、[测量计划](08_MEASUREMENT_AND_TEST.md)。本文件采用经审查的MIT decision-records方法组织上下文、选择、后果和替代，署名及许可见[第三方说明](THIRD_PARTY_NOTICES.md)。
