# 用户问题、证据来源与研究计划

日期：2026-10-22。当前状态：案头研究及代码检查；**没有开展真人访谈、没有真实使用分析数据**。

本轮主问题：相对直接Resume，用户主动选择的C/D能否减少找回下一步的负担，同时不增加难以结束或被催促的体验？

## 证据词汇

Fact 表示来源内可直接核对的事实；Evidence 表示对本问题有帮助但存在适用边界的证据；Hypothesis 表示本团队待检验判断。用户转述、研究测量和工程测试采用不同来源标签；标签不是按感觉给某个用户的可信度打分。

| ID / 标签                     | 痛点或依据                                             | 来源与适用范围                                                                                                            | 当前置信度 / 待查                                   |
| ----------------------------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------- |
| U1 Fact，利益相关者转述       | 一位朋友复习时想去手机抖音或电脑 B 站                  | 本轮用户提供的情境；未直接访问朋友、未观察行为                                                                            | 对“收到此描述”高；对频率、原因、可推广性未知        |
| U2 Fact，代码观察             | v0.1 保存现场后任务暂停，不能只靠 currentTaskId 返回   | [代码审计](01_V01_AUDIT.md) 的仓库与 TaskView 路径                                                                        | 高，工程语义；不证明用户喜欢此流程                  |
| U3 Evidence，一般人群实验汇总 | 微休息与较少疲劳、较高活力相关，总体任务表现效应不显著 | [Albulescu 等，2022](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0272460)，健康员工/学生及异质任务  | 对该综述结论中高；对 ADHD、短视频替代和本产品迁移低 |
| U4 Evidence，游戏化研究       | 参与或动机的变化不能直接当作认知或日常工作改善         | [JMIR Serious Games 2020 综述](https://games.jmir.org/2020/3/e18644)，具体人群/任务见[证据表](03_COMPETITORS_EVIDENCE.md) | 限定范围可参考；无 BackToIt 对比数据                |
| U5 Hypothesis，团队           | 离开前保留原始下一步，可能降低返回时重新找任务的负担   | 由 U1、U2 推导；未测量返回成本                                                                                            | 低，需要真实任务情境验证                            |
| U6 Hypothesis，团队           | 安静留白比轻互动更容易结束                             | 设计保护原则，不是临床结论                                                                                                | 低，必须允许轻互动胜出或两者都被否决                |
| U7 Hypothesis，团队           | 无内容岔路口可能比完整休息功能更有用                   | 简化操作成本的候选；不能假设每次离开都需休息                                                                              | 低，以直接 Resume 作对照                            |
| U8 Fact，权限边界             | 现有扩展没有手机感知/控制或全站监测能力                | manifest、浏览器适配层，见[审计](01_V01_AUDIT.md)                                                                         | 高，工程边界                                        |

## 行为原型，不伪造人物

以下使用微软 product-discovery 的“情境—目标—触发—反目标”方法组织，内容为我们自己的待验证描述，不代表真实受访者。

**电脑前想暂时离开的人**：正看课程或写作业；目标是停一会儿并留住返回线索；触发可能是疲惫、无聊、卡住或外部干扰，不能把它们当成同一种原因。反目标是又多完成一份记录、被催促或进入另一条内容流。成功信号是能在无提示帮助下说出并找到自己要做的下一步。

**已经离开、现在想回来的人**：可能已在视频网站或拿起手机；目标是直接回到原任务。反目标是必须先玩小游戏、补做倒计时或解释为什么离开。对这类人优先保留 Resume，本轮不开发自动识别。

## 用户旅程和边界场景

| 阶段 / 情境          | 当前动作与摩擦                   | 产品机会与原型处理                                    | 不应推断                         |
| -------------------- | -------------------------------- | ----------------------------------------------------- | -------------------------------- |
| 开始且状态很好       | 正在执行已知下一步               | 保持 Resume 主层级；无自动弹出、提醒或漂浮动画        | 不能因打开很久就认为走神         |
| 枯燥、想离开         | 可能打开短视频，也可能确实疲惫   | 主动次级“歇一下”，不用解释理由；允许直接离开          | 不能推断是多巴胺不足             |
| 已在 B 站，想回来    | 自己决定停止观看                 | 打开 BackToIt 直接 Resume；原型用情境说明演示         | 不读取播放状态，不识别域名来打断 |
| 已拿起手机刷抖音     | 桌面没有任何感知                 | 书面说明能力边界；未来伴侣仅作为路线图                | 不展示“检测到手机分心”           |
| 进入休息             | 不愿先填复杂表单                 | 使用已保存下一步；缺失可稍后补写；C/B/D 可比较        | 不把进入次数当价值               |
| 提前结束、自然结束   | 返回可能仍困难                   | 同一任务名、原始下一步、接着做；保留延长/今天先到这里 | 不记完成学习或失败               |
| 更长休息/不想回来    | 需要真实离开电脑                 | 最多一次明确延长；仍可结束本次；不无限循环            | 不羞辱或强行关标签页             |
| 关侧栏/重启          | 时钟和原任务可能变化             | 原型以 deadline 复算；过期显示结束，不自动返回        | 不承诺后台通知                   |
| 无任务/已归档/已删除 | 返回对象不存在或不适合恢复       | 空状态或说明；显式选择/重开才可继续，拒绝偷偷换任务   | 不创建虚假的当前任务             |
| 多窗口修改           | 同一任务下一步改变               | 标明保存版本与新版本，重新确认返回目标                | 不覆盖另一窗口更新               |
| 键盘/读屏/减少动画   | 可能无法依靠拖动、计时动画或声音 | 所有操作是有文字的按钮，稳定焦点，静态替代，无声音    | DOM 检查不等于真人读屏验收       |

## 访谈题：问发生过什么

从这些问题按时间选 8–10 题，不逐题盘问；不要询问诊断、用药、健康史或账号内容。

1. 最近一次复习中离开原任务是什么时候？从离开前一分钟开始讲发生了什么。
2. 当时你在处理哪个具体动作？下一步对你是否清楚？
3. 最先让你想停下来的是什么？当时身体或环境有哪些感受，你愿意描述到什么程度？
4. 你如何决定打开手机、视频网站，还是做别的事？
5. 后来是什么让你停下来、想回原任务？有没有没有回去的那次？
6. 回来时首先要找什么？你实际点过哪些页面或重读了哪些内容？
7. 最近一次真正有用的休息是什么样，怎样结束的？
8. 有没有一个提醒让你更烦或打断了好状态？当时发生什么？
9. 你曾试过什么工具或自己的办法？哪一次放弃了，为什么？
10. 如果只保留一句话给回来后的自己，你上次会写什么？为什么没写或写了？
11. 试用时哪一处让你想继续停留？哪一处让你想马上退出？请指出刚才的操作。
12. 与你平常的方法相比，哪一步多余，哪一步确实省了事？

## 招募、同意和分析

计划邀请 5–8 名经常在电脑学习/工作的成年人，包含不同自述习惯，不能把便利样本称作所有 ADHD 用户。朋友自愿同意后再开始，说明这是产品测试而非诊疗，不要求任何诊断。可以用合成任务、跳题、退出和要求删除记录；拒绝不会影响关系。

默认只做匿名观察表，不录屏、不收账号、不自动追踪；若需要录音或研究行为日志，另行明确目的、内容、保存地点及 7 天内删除期限并单独取得同意。未同意者可以照常体验原型。只有用户点接着做才记录该动作，不观察其他应用或私密任务内容。

分析时分别归纳“想休息”“卡住”“有别的事”“已经在刷”四类动机；保留负例、退出和不愿使用的理由，不把主观喜欢与真实返回混为一谈。[测试脚本与空白观察表](08_MEASUREMENT_AND_TEST.md) 可直接用于一次 10–15 分钟探索。

当前建议仅推进知情同意的小样本比较，保留C/D与直接Resume，B只用于有限负担对照。如果没有具体增益或多数拒绝入口，优先D/Resume，停止完整休息路线；本轮不以原型可用替代价值验证。
