# BackToIt v0.2：主动休息与同任务返回 PRD

**Status:** Draft — 待真实用户验证；原型已实现不表示正式扩展已批准。  
**Author:** 本轮产品/UX/工程协作。**Date:** 2026-10-22。  
**GitHub:** [BackToIt 私有协作仓库](https://github.com/Accelerator050717/BackToIt)，默认分支 main。尚未创建 Issue/Project；本 PRD 仍处于产品发现阶段。

## 1. Context (The "Why")

用户转述一位朋友复习时常想去刷手机或 B 站，但我们还不知道他需要休息、帮助解卡，还是只是更容易返回原任务。v0.1 可以恢复已保存的现场，缺少对“现在想暂时离开”这一时刻的主动、有限入口。本轮用独立原型检验该机会是否值得投入，正式候选优先 C 低刺激休息 / D 无内容返回，不预设娱乐有用。

## 2. Job Stories (The "Who & What")

| ID  | 情境、动机与期望结果                                                                                 | 来源                     |
| --- | ---------------------------------------------------------------------------------------------------- | ------------------------ |
| J1  | 当我在电脑前想暂时离开时，我想不用解释原因就停一会儿，同时保留回来做的动作，让返回少一次重新找线索。 | U1 转述 + H1/H2，未访谈  |
| J2  | 当我已经离开并决定回来时，我想直接看同一任务的下一步，不必先完成另一个休息流程。                     | 团队假设 H5              |
| J3  | 当休息结束但我还不想继续时，我想明确延长一次或今天先放下，并保留任务，不被判成失败。                 | 自主控制保护原则，待验证 |
| J4  | 当任务已变化、归档或没有下一步时，我想知道系统会返回哪里，由我确认目标，避免打开错误资料。           | U2 工程审计 + H6         |

优先用户是自愿在桌面执行明确学习/工作任务的成年人，不需医学诊断。事实/证据/假设详见[用户研究](02_USER_RESEARCH.md)，手机情境仅做能力边界说明。

### 完整交互流程

主界面样例任务 → 直接 Resume（不经 Detour 的基线），或次级“歇一下” → 选择 C/B 及候选时长 → 主动开始、绑定样例保存版本 → 自然/提前/三步完成 → 结束返回卡 → 显式接着做 / 一次延长 / 今天先到这里。D 从入口直接暂存一句并返回同一恢复卡，不与 C/B 绑定为必做前置。

同一时刻仅一条会话；正在休息时切换方案要先结束当前会话，不在后台隐藏多只时钟。主产品的“先放这里”继续是独立暂存概念，原型不创建第二套待办。[交互状态与文案](11_INTERACTION_SPEC.md) 是本 PRD 的可验收附录。

### 未来扩展衔接合同（本轮不接入）

`startDetour(taskId)` 先提交未完成草稿，再读仓库版本，保存最小会话快照；如果用户明确保存现场，复用 checkpoint/paused 行为，不能把 current=null 当作任务丢失。未来 `resumeDetour(taskId, expectedRevision, expectedStatus)` 必须在**同一仓库事务**内核验目标、预期revision/status及归属，然后激活，并返回经核对的资料集合。冲突时不打开资料、不自动重开归档、不换任务；用户确认新版本后才能重新提交。

现有 `activateTask(taskId)` 没有这个条件提交合同，**不能直接用“先getState检查、随后activateTask”的两次调用冒充原子恢复**。正式工程需要新增受检命令或等价事务API，并添加检查与激活之间被另一窗口修改/归档/删除的真实扩展测试，确保失败时零开页。事务提交成功后才调用现有浏览器开页适配层；点击仍不代表真正学习。

会话最小字段候选为 `sessionId/taskId/taskRevision/savedNextStep/variant/startedAt/deadline/extensionCount/status`，不是对 v1 数据库 schema 的变更承诺。正式阶段先决定是否只保存 taskId/revision 而不复制文字、如何处理 browser restart 与清空边界；需数据最小化评审和真实扩展 E2E。

## 4. Success Metrics

North Star 是更容易返回主动选择的现实任务，不能由本原型直接自动测到。研究使用两个分开的代理：是否主动点击接着做，以及能否独立说清并找到下一步；二者均不等于真的完成工作。

**基线尚未测量。** 首轮计划在 5–8 名成人的同任务交叉测试中，以直接 Resume 为个人对照；先收集基线，再谈变化百分比。本轮零真人样本，不填虚构效果。

工作放行阈值（预先选定的产品判断，非统计显著性或医学结论）：首轮至少 5 名有效参与者；对拟放行的同一个C或D候选，全部N中至少80%能独立指出同一下一步，至少60%能指出相对直接 Resume 的具体价值；报告全部分子/分母，不能只取最有利的5人或拼接不同方案的结果。无人因错误换绑暴露任务/丢记录。若2人及以上表示被催促或因互动想不断延长，暂停娱乐方向。详细分母、退出、时间窗、缺失与保护指标见[测量计划](08_MEASUREMENT_AND_TEST.md)。

## 5. Scope & Constraints

**本轮 In-Scope**：审计、研究、A/B/C/D比较、完整企划和测试计划、独立样例原型、工程和视觉验证。**正式候选范围**：主动入口、C/D、同任务返回、安全退出；前提是 Gate 1 真实研究通过。

**Out-of-Scope**：正式 Detour 合并、v0.2发布、数据库迁移、新权限、通知/自动监控B站、手机App识别/控制、跨设备同步、二维码携带私密任务、内容库运营、Fun Fact事实生成、AI、强制阻拦、积分/签到/无限复玩和医学疗效。

**依赖**：现有本地 v0.1、已安装 Node/pnpm/Chromium、用户自愿参与研究。原型不是 Chrome 扩展 E2E，也不证明手机能力。UI复用视觉token值，不导入生产App/仓库；依赖解析与构建污染风险见[审计](01_V01_AUDIT.md)和[实际测试](12_DELIVERY_AND_VALIDATION.md)。

**主要风险**：用户不会主动打开；两种体验都不如直接返回；互动增加认知负担；下一步本身不够具体；临时会话副本暴露或在删除后复活；浏览器后台节流；本机时间改变；同设备共享环境；有限便利样本偏差。保护性约束能限制风险，不能证明产品价值。
