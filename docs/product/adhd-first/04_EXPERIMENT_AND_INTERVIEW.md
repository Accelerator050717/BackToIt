# 两阶段产品研究：从主动打开到现实第一步

版本日期：2026-10-23（America/Los_Angeles）。当前真实参与者：0；第一阶段未开始，第二阶段未开始，Gate1 未通过。本文提供主持人可以执行的脚本和空表，不包含用户试用结果。

研究主问题：在用户已经想开始或想回来时，Tiny Start / Tiny Spark / Quiet Pause / Park & Return 是否比直接 Resume 多提供一项实际帮助，并且没有增加难以结束、被催促或填写负担？喜欢、点击、在界面停留都只作为解释线索。

## 参加和记录方式

第一阶段计划 5 至 8 名自愿成年人，每人 10 至 20 分钟。按「经常启动不了」「切换后忘记现场」「想找刺激」「想安静/厌烦提醒」等自述使用习惯邀请不同的人；允许同时符合几种，也允许只说日常困难。只确认已成年和愿意用电脑样例，不问诊断证明、病史、用药、工作单位、收入或真实任务正文。便利样本不能代表全部 ADHD 成人。

主持人默认不录音、不录屏、不采集网站或设备日志，不打开参与者浏览器账号。原型只使用合成任务。匿名 ID 由主持人临时分配；联系安排与观察记录分开保管，不进入项目目录、GitHub 或第三方表单。本文和仓库只保存空白表。

测试前分别询问「愿意体验」与「同意记录」。拒绝记录仍可自行体验，不纳入行为数据。允许跳过任意问题/路径、不解释就停止。默认记录只含方案、操作数、相对秒数、观察/自报标签、概括理由；引用原话须另问是否允许匿名保留，且不能含可识别内容。

实际研究记录由主持人保存在自己的受控本地位置，7 天内删除逐人记录；此前仅在参与者同意后形成不含原话及身份的汇总。参与者可用研究 ID 要求删掉记录，无需交代理由。撤回时询问是否允许只保留「一人退出」的无内容计数；不同意则同步重算分母。不要承诺已删除外部副本，研究默认就不创建这些副本。

## 可直接朗读的同意话术

> 我们在研究一个帮助成年人重新开始任务的小工具，不评估你的专注能力，也不提供诊疗。请只用示例内容，不输入自己的学习、工作或健康资料。你可以只看一部分、跳题、直接关闭，或随时决定不参加，不会影响任何关系。默认没有录音、录屏或自动追踪。我希望手动记下不含身份信息的操作观察和概括理由，逐人记录会在 7 天内删除。你可以用这个临时编号要求提前删除。你愿意体验吗？你是否也同意我做上述记录？

两项答案分别记录。不参与或不同意记录就结束采集，不反复说服。后续真实时段另行征求自愿同意；本次同意不自动覆盖第二阶段。

## 第一阶段：探索入口、完成分支、观察第一动作

主持人准备：启动新版独立原型；确认样例标识、语言、键盘和减少动画设置可用；不打开开发加速或错误注入；准备公开合成练习页/纸面示例。示例下一步使用「打开例题 2，分别写出 dx/dt 和 dy/dt」。第一现实动作可定义为在示例纸上开始写其中一个导数；不评价答案对错。只需要下一步的可执行性，不要求数学能力；不愿做数学可用等量公开示例「打开示例信件，写出第一句称呼」，事前固定，不按结果换题。

| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 0 至 2 分钟   | 读同意话术，确认输入方式和是否希望少动画                                                                                                     | 分开记录体验与记录同意；不要求披露 ADHD 身份                                                                                        |

10 分钟版本：过去经历和首页自由观察各保留约 2 分钟，仅体验一个候选及直接 Resume，再做负例复盘。不要为塞满五条路径压缩同意或迫使参与者赶时间。

Tiny Start 从参与者明确表示愿意开始时就观察；动作可发生在不计时/30秒辅助进行中。照实记录 t动作，允许它早于 t点击，不要求先点 Resume 或等计时结束。其他休息路径在表达想返回后观察第一动作；这些顺序不是必须遵守的使用流程。

### 呈现顺序与适用情境

在第一次自由观察之后再介绍候选，避免提前教会入口。后续比较用轮换顺序，不总是先玩再安静；下表是预先排定的探索顺序，不能称随机对照试验。R＝直接 Resume，T＝Tiny Start，S＝Tiny Spark，Q＝Quiet Pause，P＝Park & Return。这里的 S 仅为顺序代号；下文证据标签 S 表示参与者自述，记录时须填完整列名，不能混用。

| 临时顺序编号 | 可提供的比较顺序 | 备注                                |
| ------------ | ---------------- | ----------------------------------- |
| 1            | R、T、S          | 启动不了 / 想找刺激两种独立情境     |
| 2            | S、R、Q          | 想找刺激 / 真累了，不要求在疲劳时玩 |
| 3            | Q、P、R          | 真累了 / 想起别的事                 |
| 4            | P、R、T          | 暂存冲动 / 已知下一步仍起不来       |
| 5            | T、Q、R          | 启动不了 / 需要休息                 |
| 6            | R、P、S          | 直接返回 / 想起别的事 / 想找刺激    |
| 7            | Q、R、T          | 与 5 的顺序不同                     |
| 8            | S、P、R          | 与 6 的顺序不同                     |

参与者可以只试一部分、改选更符合意图的路径，记录原计划、实际顺序和原因。所有人无需遍历五种模式；每种形式的已提供、已尝试、拒绝和缺失分开报告。练习效应、不同意图、所选时长和操作量都可能影响结果，因此只做逐人描述性比较，不把差异归因于单一形式。

同一人情境追问可使用：T「下一步太大」；S「还不想安静，想动一点」；Q「已经累了，可能离开屏幕」；P「怕忘记一件无关想法」；R「现在就想回来」。这些是设定情境 H，不代表参与者真实状态。

## 第二阶段：一次自愿真实学习/工作时段

目的：了解真实需要发生时，用户是否想起、主动打开、愿意结束，并尝试了自己的第一个现实动作。第一阶段可发现性和主持人安排体验不能回答这个问题。

当前原型保持合成任务，不能导入真实任务或用户资料。参加者可以把真实下一步留在自己的纸上或现有本地工具中，不向主持人展示，原型里的卡片仍明确是演示。真实时段里把它作为可选的一般协助入口，不声称演示卡认识其真实任务。这个版本的 field probe 无法验证「正式扩展里自动恢复本人任务卡」的收益；该问题需要以后另行批准的本地集成研究。若参与者觉得这个限制使试用无意义，记录拒绝原因，不能要求迁移资料来绕过隔离。

执行步骤：

1. 另行说明并取得第二阶段同意：「你可在自己选择的一次学习/工作时段试用，也可完全不用。不需要摄像头、录屏或实时汇报，不要把真实内容输入原型。时段结束后只需回想最后一次想离开/开始的时候。可以不回答或撤回。」时段长度由参与者选择，不强制 25 分钟或整天。
2. 参加者自己保留入口，自行选是否关趣味、用计时或不使用。不设推送提醒，不定时发消息叫其打开，不盯手机/网站。主持人离场，不采集自动事件或私密页面。
3. 时段结束后一次可选的 3 至 5 分钟复盘，先问是否确实出现过相关需要，再回顾最后一次需要。未出现、想起但没开、没想起、选择其他工具和中途退出都保留。没有及时回答就记失访，不能猜测成功或失败。
4. 仅记录下方自报表。不问具体任务正文、抖音/B站账号、观看记录或工作成果；参与者可以只说「先打开了材料」「写了第一行」等动作类别。若参与者主动说出敏感细节，不抄入记录，提醒可以概括。
5. 询问「下一次会想起什么入口？有没有因为这次试用反而更难开始/停下？哪一步最好删掉？」之后按承诺删除逐人记录。研究没有后台追踪，无法核实自报或持续专注。

### 真实时段复盘脚本

1. 今天这个时段里，有没有出现想开始、想离开或想回来的时候？没有也可以。
2. 如果有，请只想最后一次：当时首先想到什么做法？工具是否在你的选项里？
3. 你实际打开了它吗？没有打开最主要的原因是什么？不用解释真实任务内容。
4. 如果打开了，你用了哪条路径，什么时候离开工具？有没有还想接着玩的时刻？
5. 这段过程中是否实际开始一个动作？是在辅助进行中、结束后还是点击返回后？可只讲动作类别，不讲内容。未开始时卡在哪一步？
6. 你是自己想到的、先前约定提醒的，还是别人提示的？实际用别的方法是否更顺？
7. 有没有被催、步骤太多、担心隐私、根本不愿打开，或想关掉某项功能？这次有没有可保留的一点帮助？

## 分母、时间点和证据标签

O＝经同意在样例任务上直接观察；S＝参与者自述；C＝仅界面点击；M＝缺失/不可观测；F＝工程故障；X＝拒绝/退出。按钮 C 不能升级为 O 或 S 的真实动作。所有数字同时给 n/N，不合并 O 和 S；不报告显著性、临床改善或泛化的效率百分比。

N1＝第一阶段同意记录并开始自由观察的人，包含随后只用 R、拒绝候选和退出的人。不同意记录者仅报招募流程总数且需允许保留该总数，不进入行为分析。Np＝该候选实际被提供的人，包括拒绝该候选者；未提供者另列。Ap＝实际开始该候选的人，包括技术失败、中途关闭；工程成功的子集单列，不能静默删掉失败。撤回数据按同意范围移除后重算所有相关分母，并说明人数变化。

N2v＝自愿开始第二阶段的人；N2r＝自愿完成复盘的人；N2need＝N2r 中自述发生过至少一次相关需要的人。不愿第二阶段的人数/邀请人数、失访/N2v、没有需要/N2r 都报告。未复盘者不能进入「有需要」分母，也不能被算作未打开；其缺失会限制结论。人是主要分析单位，每人最后一次相关需要作主记录，重复互动只当负担线索。

## 允许删掉候选的决策规则

这些是产品继续研究规则，不是统计学效果阈值，也不会自动授权正式集成。

- 任意一次错绑任务、恢复已删内容、真实资料外传、失去退出能力或明显持续不适：暂停相关候选，先查工程与同意流程，不等人数凑满。
- Tiny Spark 即使最受欢迎，只要两名独立体验者指出它让结束/回任务更难，并有对应行为或具体经历，就优先删除或收紧。只有喜欢度高、明确价值全靠主持人提示，也不推进该候选。单个严重负例也可立即停用。
- Tiny Start 若频繁拆错、把建议当成原记录、要求反复改写，先缩减为用户原下一步和手动最小动作；原规则不能靠 AI 宣传掩盖。若它是唯一有具体帮助的路径，路线图只保留它与 Resume。
- 多数人偏好直接 Resume 或说额外选择多余，优先优化首页和记录下一步，删除整个卡住层级是合格结果。Quiet 不获选也不能解释为用户「不懂休息」。
- 第一轮至少 5 人后才做一轮跨人的探索归纳；任一候选少于 5 人被提供/观察，或有大量跳过/故障，只能称线索。不能挑最好 5 人、拼接不同候选数据或排除拒绝者来宣称通过。5 至 8 人足以暴露可用性问题，不足以证明真实使用价值。
- 只有第一阶段问题可解释、候选无需主持人帮助即可结束，才邀请自愿的第二阶段。第二阶段必须报告想起但没开、没想起、拒绝和失访；若所有积极反馈都来自提示后试用，真实价值仍未知。人数不足或没有相关需要就继续研究或停下，不补造效果百分比。
- 任意阶段的正面结果都只支持该版本、该样本与场景下的产品判断。任务绑定收益、持续使用、长期工作表现与临床效果保持未验证；正式发布建议由 [06_RELEASE_RECOMMENDATION.md](06_RELEASE_RECOMMENDATION.md) 单独审查。

研究依据及 O/E/R/H 边界见 [02_EXECUTIVE_FUNCTION_MAP.md](02_EXECUTIVE_FUNCTION_MAP.md)。当前没有访谈记录、招募联系或真人数据进入仓库。
