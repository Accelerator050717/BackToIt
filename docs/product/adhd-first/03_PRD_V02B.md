# BackToIt v0.2b ADHD-first PRD

日期：2026-10-23（America/Los_Angeles）。状态：Draft / Research prototype。产品类别：面向 ADHD 相关任务启动与切换困难的成年人使用的任务重新进入辅助工具。正式 v0.1 不变，旧 Detour 保留对照。本文件定义验收合同；**条目列入 PRD 不代表已经测试通过**，实际执行结果只见[07 报告](07_TEST_AND_SKILLS_REPORT.md)。

## 1. 问题、证据与目标

用户提供了朋友复习时想看手机/视频的真实转述，也明确希望 ADHD 困难成为产品机制的出发点。目前没有招募受访者、真实会话数据或医学效果证据。NIMH 等官方资料支持需要关注启动、计划/记忆、分心与刺激需求，但不能证明本应用有效；竞品主张只能作设计参照。证据等级、来源和负例见[执行功能地图](02_EXECUTIVE_FUNCTION_MAP.md)。

北极星是**更容易对自己选定的现实任务迈出下一步**。本轮用独立合成数据原型检验机制可用性与研究可执行性；下一阶段比较“直接 Resume 已足够”和“需要额外帮助”的真实情境。不以打开次数、停留时间、完成三次互动或连续打卡代替价值。

可检验假设：H1 一项可修改的最小行动可能降低启动负担；H2 确定且有终点的触觉小互动可能为部分人提供愿意主动选择的岔路；H3 安静、无必填的一句暂存适合另一些时刻；H4 多条路径也可能增加选择负担，直接 Resume 可能更好。所有假设允许否定。

## 2. User stories 与非目标

| ID  | 情境、需要与结果                                                 | 主要风险                                 |
| --- | ---------------------------------------------------------------- | ---------------------------------------- |
| J1  | 我知道任务却开始不了，希望先看到一个可立即做的动作，并允许修改它 | 建议不合适，反而多出编辑工作             |
| J2  | 我想找一点刺激，希望主动做一件小而有终点的事，然后回原任务       | 好玩却难结束，替代了现实动作             |
| J3  | 我真的累了，希望离开屏幕也能保留回来线索                         | 倒计时变成催促；工具暗示不该休息         |
| J4  | 我突然想到别的事，希望用一句话放下，不必切换成新任务             | 变成第二套待办或新的整理负担             |
| J5  | 我已经愿意回来，希望立即看自己的下一步，不必先完成帮助流程       | 帮助层挡住主任务                         |
| J6  | 原任务在别处变化/删除，希望工具诚实解释，避免带我回错地方        | 陈旧快照复活、无意恢复归档或错绑其他任务 |

非目标：诊断/治疗、症状或注意力评分、全日计划器、自动检测分心、网站阻拦、手机控制、通知权限、真实任务导入、账号/云同步、远程 AI/Ollama、随机奖励、内容流、公开发布、v0.1 集成或 schema/权限变更。原型不展示假装已经获得的权限。

## 3. 信息架构与状态合同

首屏顺序为“当前明确选中的演示任务 → 用户保存的下一步 → 接着做（唯一主要动作）→ 我卡住了 / 先放这里（次级）”。两种演示任务均用合成内容，可切换且遵守相同版本合同。没有下一步时写“尚未记录下一步”，不能用本地建议冒充用户记录。

```text
任务首页 ──直接接着做──────────────────────────────→ 返回意图确认
    ├─我卡住了 → 开始不了 → 一项建议可修改 → 不计时开始 / 自愿30秒 → 原任务卡
    │          ├想刷点别的 → 三片小图 → 第三片完成 / 到上限 / 提前结束 → 原任务卡
    │          ├真的累了 → 自选45/90/180秒安静休息 → 到时 / 提前结束 → 原任务卡
    │          └想到别的事 → 一句暂存或跳过 ───────────────────────→ 原任务卡
    └─先放这里 → 同一句暂存路径 ────────────────────────────────→ 原任务卡
```

任何帮助路径均可直接返回或退出；不要求先完成动作、计时或填写。退出不删除任务，不记学习失败。返回成功仅表示**原型记录了返回意图**，不表示真实动手、完成任务或持续专注。

会话绑定 `taskId + revision + 用户保存的下一步快照`，不能靠当前任务指针找目标。返回时核对当前持久任务的同 ID、存在性、状态与 revision；冲突必须阅读/确认新版本，归档必须显式重开，删除/无目标不能恢复。不同任务的最新内容不能自动替换原会话目标。

时间状态使用 `startedAt/deadline` 与显式阶段，不靠累计 tick；刷新、后台、关闭重开后按时间戳恢复，过期只显示原任务返回卡，不自行激活。Tiny Spark 第三片完成立即结束，时长是**上限**，不是必须停留多久。30 秒也只是自愿辅助，不是医学剂量。

## 6. 验收示例与正式接入合同

正常：演示任务A保存下一步 → Tiny Spark两片 → 提前结束 → 卡片仍为A及其原文 → 主动Resume → 只记录演示返回意图。另一例：任务B → Tiny Start改写建议 → 自愿30秒 → 离开页面 → 过期重开只显示B卡片，不擅自启动或标完成。

负例：会话绑定A revision2，另一窗口把A改成revision3，再选择B。旧窗口返回时必须先说明A变化；不得切到B。A已归档要求显式重开，A被删除只能安全退出。空下一步不能声称“知道你接下来做什么”。强制localStorage写入失败后仍须保留失败信息，不能把返回点击、计时或三片完成算作现实行动。

未来正式扩展必须先 await 未提交草稿 flush，取得持久记录后再建立会话。现有v0.1保存现场可能清空currentTaskId，不能据此认为任务丢失；现有`activateTask`没有expectedRevision合同，不能用“先读再激活”的分离调用冒充原子检查。设计与审计细节保留在[v0.1审计](../01_V01_AUDIT.md)。本轮只用独立样例存储检验交互形状。

## 7. 研究指标与放行

主问题是用户会不会**主动想到并使用工具、之后是否开始一个现实动作**。第一阶段记录理解/操作/独立说清下一步/被催促/想续玩/拒绝与原因；第二阶段记录真实时段中的自发触达与自述现实动作，区分观察、用户自述和未知。当前第二阶段也只用合成原型；真实下一步留在参与者自己的纸上/本地工具，不向主持人透露，故不能证明真实任务绑定卡的收益。点击返回只能计为返回意图；不自动推断动手或持续专注。操作数从表达想开始起记录，等待只计可观察窗口，不假装知道后台发生了什么。

按全部参与者、每方案实际暴露/自选者、退出与缺失分别报告分子/分母，小样本用描述性比较，不编显著性和改善百分比。Tiny Spark受欢迎但难结束时优先删除；只有Tiny Start有价值则路线图收窄；若全不如直接Resume则回到原恢复核心。预注册式工作阈值与完整观察表见[实验方案](04_EXPERIMENT_AND_INTERVIEW.md)，不能临场挑最有利分母。

当前参与者0；Gate1未过、Gate2未开始。工程可运行允许交付研究原型，不允许正式集成、医学效果宣传或公开发布。下一阶段选择见[发布建议](06_RELEASE_RECOMMENDATION.md)。
