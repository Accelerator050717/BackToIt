# v0.2b 决策与取舍

日期：2026-10-23（America/Los_Angeles）。决策者：本轮产品/UX/工程协作。下述“采用”只指独立研究原型与文档；正式扩展均未批准。旧 [2026-10-22 决策](../06_DECISIONS.md)与 [C/D 优先 PRD](../05_V02_PRD.md)原样保留，不用新产品目标伪装成新增用户证据。

## D01：围绕困难设计，主线先验证 Tiny Start

情境：v0.1擅长保存/恢复现场，旧v0.2主要比较主动休息；用户新目标明确包括“知道任务却开始不了”。[NIMH成人资料](https://www.nimh.nih.gov/health/publications/adhd-what-you-need-to-know)支持关注计划、记忆、较大任务和分心困难，不支持某个按钮或秒数有效。

采用：以已保存下一步为锚，一项本地最小行动建议可接受/修改，默认不计时，自愿选择30秒辅助。建议与用户记录分开，点击与真实动手分开。Tiny Start是优先**验证**的主线；四条需要均可体验，没有证据排名。

替代：沿用C/D优先很省开发，但不足以覆盖启动；自动AI拆解可能更灵活，但引入隐私、语义不确定和更多选项；写十项任务清单扩大负担。代价：规则容易机械、不适合全部任务，需要用户修改。推翻条件：用户认为建议没有帮助或多出填写负担，直接Resume更轻，则缩减或删除建议层。不能用更多规则掩盖价值缺失。

## D02：趣味保留，奖励循环不保留

采用：Tiny Spark是一幅**固定三片的小图**，每次把可预测的一片接上；三步后立即完整并回任务卡。使用普通按钮支持触控/鼠标/键盘；选择45/90/180秒只作为上限，随时提前结束。细微反馈表示“刚才动作发生了”，减少动画时保留静态位置与文字进度。没有分数、胜负或内容解锁。

为什么值得真正做：用户明确不希望产品只剩克制，也不能把“ADHD适合低刺激”当定论。可触摸、可预测、看到完整形状的片刻可能提供愿意主动选的岔路。这是需要验证的吸引力假设，不叫“多巴胺补充”或“脑重置”。

| 形式                                          | 决策与原因                                                   | 什么证据会改变决策                                     |
| --------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------ |
| 固定三片微拼接                                | 保留并实现；比单纯三个计数按钮有形状与触感反馈，仍有清晰终点 | 若操作本身难懂/无趣/增加返回成本，改形或删除           |
| 旧三步接线                                    | 保留旧原型作形态对照，不删除历史方案                         | 在同意图条件下有人能更轻松结束，可选择旧形式           |
| 静态Quiet / 无内容Resume                      | 始终保留，可能比趣味更适合当下需要                           | 若没人需要休息，收窄默认入口而不删除自主退出           |
| 精选有限事实卡                                | 本轮不做，仍属候选；文字、事实维护和跳读可能抢占下一步       | 参与者主动提出具体需要且可证明不会增加停留，再独立比较 |
| 随机惊喜/战利品/转盘/虚拟币/排行榜/连胜       | 删除方向；目的是持续互动，与返回现实任务冲突                 | 不以点击率或喜欢程度重新引入                           |
| 自动“再来一次”、更多图案、无限续时、视频/feed | 不做；从有限岔路变成内容目的地                               | 若用户需要真正休息，支持离开工具，不用增加内容解决     |

重要代价：固定内容新鲜感会下降。这不是自动加内容的理由；若工具必须不断新鲜才有人使用，可能不符合本产品任务。检验的是“自然结束后愿意回到自己选的动作”，不是看完成拼图的人有多少。

否决原则：Tiny Spark即使更受欢迎，只要有人指出难结束，应先检查机制；重复出现难结束/催促/延长冲动，则暂停其正式候选资格。具体样本分母与停止标准见[研究协议](04_EXPERIMENT_AND_INTERVIEW.md)，不等满样本才处理明显伤害。

## D03：按需要展开，默认不先做四选一

采用：首页当前任务、用户原文、主要“接着做”；“我卡住了”次级展开四种需要；Parking另有直接入口。四条需要不能强行串行，用户无需先解释原因。设置可隐藏趣味，不做“ADHD模式”总开关。

替代：四张等大的首页卡提高可见性，也更像另一个任务菜单；只留一个按钮最轻，但可能隐藏有价值的启动支持；诊断问卷精细分型会增加敏感收集且无必要。代价：主动展开可能降低发现率。验证：不提示先观察能否找到；再比较更直白“想歇一下”等文案。若入口不被想到，先研究使用时刻，不能直接用监控/弹窗补触达。

## D04：用户原文、规则建议、真实行为各有边界

采用：保留已提交下一步原文。规则只能建议一个动作，不知道内容就用明确通用动作或请用户自己改写，不能编造题号/页面/已完成步骤；建议不会偷偷成为保存记录。30秒与完成三片都不等于学习成功，Resume仅是显式返回意图。

替代：自动覆盖原下一步可以减少一个确认，却失去用户来源；用点击率当成功很方便，却不能回答价值。代价：用户可能多一个接受/修改动作。验证时把这一步计入操作数和负担；必要时取消建议，仅展示原文。

## D05：同任务返回是安全合同

采用：所有路径绑定同一个明确taskId/revision；跨窗口变更要求查看并确认新版；归档需显式重开；删除/无目标不恢复。不能根据“最新当前任务”改绑。演示两种任务均遵守相同规则。存储失败不提示成功，坏数据不静默清空，重置只清新原型key。

技术依据：[v0.1审计](../01_V01_AUDIT.md)记录暂停会清空current指针、卡片可能显示未提交草稿，现有activateTask并非条件恢复。正式阶段须先flush，再在一个仓库事务中检查目标/版本/状态并激活，提交成功才打开资料。

替代：复制完整Task与资源最方便但增加敏感副本；只绑定current指针有确定的错绑风险；先getState再activate有竞态。代价：多出冲突/删除路径，以及未来扩展真实并发测试成本。此次不为解决它修改v0.1。检查通过是工程正确性，不是ADHD价值证据。

## D06：独立原型，不借研究直接升级生产

采用：`prototypes/adhd-first/`独立入口，端口4178，新localStorage命名空间，合成任务；不导入生产仓库/IndexedDB/chrome API、不调用Ollama/云模型、无自动analytics/远程资源。旧`prototypes/detour/`保留。复用已有本地依赖、配置经验和视觉值，不把原型放进WXT入口。

替代：正式扩展实验开关更真实，却可误写生产；只交静态稿无法验证时间/冲突；新云后端没有此轮收益。代价：不能证明真实扩展侧栏、浏览器权限、真实任务恢复或跨设备能力。第二阶段真实时段也保持合成原型，见下文；需要真实任务卡的收益必须另行批准本地集成研究。

本轮技能取舍：实际读取本地`frontend-design`及其Apache-2.0许可，应用到任务优先层级、清楚动作、把反馈集中在拼接上与错误文案；没有复制素材/代码或引入远程字体。PM方法沿用已有PRD的“问题—需求—验收—证据”可审阅结构，自主写本轮内容，不声称重新运行旧Skill审阅。完整技能状态以[07报告](07_TEST_AND_SKILLS_REPORT.md)为准。

## D07：手机抖音分心——独立路线决策

这是用户提供的真实情境，但桌面Chrome扩展不知道手机正在发生什么，也不能控制它。不把手机无回应解释成用户不努力。以下路线是独立决策，未开发手机端、未请求通知/屏幕使用权限、未上传任何真实任务到二维码。

| 路线              | 能解决/不能解决                                                                                                       | 成本、身份与控制                                                                         | 新摩擦/隐私风险                                                                                             | 阶段建议与验证                                                                                             |
| ----------------- | --------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 1.仅桌面          | 可见主动入口、绑定已存下一步、启动辅助；用户回电脑时仍有线索。不能检测手机刷视频，也不能把人从手机拉回来              | 不新增身份/同步/手机权限；复用本地仓库合同                                               | 最大风险是用户根本不会回桌面打开工具；不能用原型偏好掩盖触达失败                                            | **当前选择**。第二阶段问“有没有想起、有没有真的打开、为何没开”，把拒绝和没想起计入结果                     |
| 2.轻移动配套      | 用户主动扫码打开无私密数据的公共入口/系统分享捷径，可给通用最小动作提示。没有同步就不能展示桌面私密任务或声称接上现场 | 低至中成本；无账户的公共入口最轻。分享/快捷方式需各系统适配和单独同意                    | 扫码本身多一步；手机入口可能增加停留。URL/query/二维码不得带任务标题、下一步、token；不假装已同步           | 仅在证实桌面触达是主要缺口后做概念研究。先比“只给公共入口”和“自己纸上留下一步”，无敏感数据可行再申请小试验 |
| 3.正式同步移动App | 可能在手机主动查看自己的任务；仍不能默认检测/拦截其他App，系统许可与平台限制需独立研究                                | 高成本：账号/跨设备身份、加密与密钥、冲突合并、离线删除传播、备份、导出/删号、支持与维护 | 登录与安装负担，手机/桌面任务隐私、共享设备、数据驻留与服务成本；通知可能焦虑。不能把“加个二维码”当同步方案 | **不立项实现**。需独立需求证据、数据流威胁模型、权限/成本评审和用户授权，再决定是否值得投入                |

后续触发条件：若自愿真实时段反复出现“需要时人已在手机、桌面入口不可达”，先研究路线2的主动、无私密内容入口；若真正需求是“手机看到我的原任务”，路线2无法满足，应清楚进入路线3的成本决策，不偷偷传文字。即使如此也不自动获得监控手机的理由。

## D08：用真实行为推翻方案，而非收集喜欢

采用：阶段1为5–8名自愿成人的10–20分钟探索，轮换呈现顺序；可只试部分路径，不问药物/诊断证明。阶段2为自愿者一次真实学习/工作时段的需求探针，不摄像、不追踪B站/抖音、不导入真实任务；真实下一步可由参与者自己留纸上/现有工具，不向主持人透露。只记录非敏感、自愿自述的触达/开始/摩擦。

重要局限：当前原型仍显示合成任务。阶段2能检验“是否想起、主动打开可选协助、能否结束与尝试现实动作”，**不能证明生产绑定卡的收益**。它不能替代未来另行批准的本地集成研究，也不是临床试验。

替代：只问喜欢容易偏向Tiny Spark；自动遥测拿不到真实动手且多隐私成本；在主持人提醒下打开不是自发使用。代价：自述有回忆偏差、小样本不能推断总体。报告观察/自述/未知、显式分母、提前关闭与拒绝；不能只挑最有利的成功者。

## 开放决策及可推翻点

1. “我卡住了”是否比“想歇一下”更易懂且不标签化？由发现性与用户原话决定。
2. 本地规则的一项建议是帮助还是多一步？若后者，回退原文和直接Resume。
3. Tiny Spark有吸引力且容易结束吗？两者缺一不可；不能用停留更久证明更好。
4. 默认90秒适合哪种意图？目前只是45/90/180的中间研究值，无临床最佳值。
5. 桌面入口在真实想刷手机时是否根本不会被打开？若是，产品问题先于UI问题。
6. 直接Resume是否已解决多数时刻？若是，保留最小恢复核心，不为扩大功能而扩大问题。

目前全部是待研究的问题。原型可用与保护边界通过，只能让下一次研究可执行，不能宣告方向已被用户证明。
